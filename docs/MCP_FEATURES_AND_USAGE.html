Control Towerplaybook draft, revision, 실행, 상태, 분석 제출revision 승인과 write 승인, scheduler는 사람/별도 시스템 영역이다.

4. Aside/Chrome CDP 경로

  1. 사람이 aside/Chrome에서 장비에 로그인한다.
  2. Chrome을 loopback CDP로 실행한다.
  3. sangfor_console_capture_evidence 또는 sangfor_attach_observation_session이 기존 page에 attach한다.
  4. 지정 메뉴를 read-only로 탐색하고 screenshot 또는 encrypted capture를 만든다.
  5. AuditLedger 또는 capture bundle의 hash와 provenance를 검증한다.
sangfor_console_capture_evidence는 Chrome을 대신 로그인시키지 않는다. 기존 로그인 page와 CDP endpoint가 없으면 현재 live evidence를 만들 수 없다.

5. 안전·승인 모델

read-only → plan → dry-run → signed approval → single-use nonce
→ safety class → real execution flag → read-back verification → audit evidence
  • HTTP 2xx는 성공이 아니다. 독립 read-back PASS만 성공이다.
  • INDETERMINATE는 PASS가 아니다.
  • 실패 시 자동 rollback하지 않고 FAILED_HALT한다.
  • 모호한 UI target, 누락된 service catalog, 손상된 nonce/ledger는 거부한다.
  • secret은 persistence 전에 masking한다.
  • HTTP bridge remote write에는 token, signed approval, SANGFOR_ALLOW_REMOTE_WRITE=true가 추가로 필요하다.
