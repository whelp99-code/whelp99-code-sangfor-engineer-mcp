# 후속 개선 — 실제 의미 검색과 재정렬 검증

상태: 진행 중. 선행 코드 d1fc62d. 작업 이슈: https://github.com/whelp99-code/whelp99-code-sangfor-engineer-mcp/issues/84. 사용자의 최신 지시로 LightRAG 도입 및 자동 전환은 제외한다. 과거 3차 개선안의 조건부 전환 문구보다 이 결정이 우선한다.

## 순서와 완료 기준
1. 로컬 모델 서비스의 요청/응답 모델과 commit revision을 검증한다. 부정확한 모델 표시, 잘못된 응답 인덱스/벡터는 거절한다. loopback에서만 새 서비스를 실행한다.
2. 기존 정제 코퍼스 전체 66,767 청크를 검증된 다국어 임베딩으로 새 후보 파일에 재생성한다. 원본과 운영 인덱스는 유지한다. 모델을 실제 로드하여 embed한 벡터만 의미 검색으로 인정한다.
3. 평가 CLI에 실제 비동기 검색 경로를 연결하고 BM25, Dense, 가중 Hybrid, RRF를 고정된 21문항/12문항으로 비교한다. 다른 설정은 별도 실험으로 보고하고 기존 동일설정 비교 게이트를 약화하지 않는다.
4. 로컬 Cross-encoder 재정렬을 선택적으로 연결하고 같은 평가로 검증한다. 성능이 낮으면 기본값으로 승격하지 않는다. 실패·타임아웃은 관측 가능한 기존 순위 복구로 처리한다.
5. 남은 실패를 원문과 근거 청크로 확인하고 데이터 라벨 문제/후보 검색/재정렬 문제를 구분한다. 기존 정답·임계값은 바꾸지 않는다. 개발용 질문에 맞춘 고정 문서 ID 규칙은 금지한다.
6. 구현 테스트, lint/build, CI, 모델/데이터/코드 해시와 실측 결과를 기록한다. 개발·후보 검증과 운영 배포를 구분한다.

## 위험
모델 이름만 같고 revision이 다르면 비교를 거절한다. 의미 검색은 높은 코사인 유사도를 무응답 여부의 증거로 취급하지 않는다. CPU 지연과 정답 회귀를 함께 보고하며 고정 평가에서 나쁜 모드는 자동 활성화하지 않는다.

## 실패 분석과 적용한 수정
- Snapshot restriction 및 static routes 문서는 실제 설명·절차가 존재했다. `restriction/restrictions`, `route/routes`가 서로 다른 토큰이어서 질문이 범용 설정 문서로 밀렸다. 명시적인 기술 명사 단·복수형 사전을 BM25에만 적용했다. 파일 경로, 인터페이스 식별자, CLI 옵션, status/chassis/analysis 등은 보존한다.
- RAID 정답 소스는 RAID 카드 장애 시 물리 노드를 격리하는 내용이다. 질문의 ‘장애 디스크 자동 격리’와 정확한 대상이 달라 라벨의 의미 적합성에 사람이 재검토할 부분이 있다. 점수를 위해 질문·정답을 수정하지 않는다. 정답 문서 적중이 정확한 답변이나 적절한 조치의 증거는 아니다.
- 별도 12문항은 이미 결과가 노출되어 이번 개발에 활용했으므로 이제 개발 회귀셋이다. 독립 holdout 또는 현장 검증으로 부르지 않는다.

## 운영 범위
기존 운영 프로세스와 .env를 변경하지 않고 loopback 8004(임베딩), 8005(재정렬)에서 검증한다. 공개 모델 가중치만 내려받으며 문서 내용은 외부 모델 API에 전송하지 않는다. 새 인덱스는 후보 파일이며 자동 승격하지 않는다.

## 로컬 모델 선택
동일한 무작위 32청크 처리에서 E5-small은 7.31초, 기존 캐시의 multilingual MiniLM은 2.08초였다(동시 부하가 있는 처리량 probe이며 SLO가 아니다). 전체 E5 재임베딩은 후보를 발행하기 전에 중단하고 MiniLM의 고정 revision으로 전체 후보를 새로 생성한다. E5 전체 검색 품질은 측정했다고 주장하지 않는다. MiniLM의 모델 기본 입력 한도는 128토큰이므로 긴 청크의 뒷부분이 잘릴 수 있으며 실측 품질에 이 한계가 포함된다.

선정한 임베딩: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2, revision e8f8c211226b894fcb81acc59f3b34ba3efd5f42, 384차원, loopback 8006. E5 검증 서비스는 8004에서 별도로 확인했다. 재정렬: cross-encoder/mmarco-mMiniLMv2-L12-H384-v1, revision 1427fd652930e4ba29e8149678df786c240d8825, 최대 입력 512토큰.
