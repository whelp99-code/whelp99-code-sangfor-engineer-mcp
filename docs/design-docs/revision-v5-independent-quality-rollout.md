# 5차 개선: 독립 평가에서 운영 검증까지

상태: 진행 중. 이슈 #86. 선행 코드 292eb111a99ee7eb2ddff67b65c0e96cda6fa380. LightRAG 미도입.

## 승인된 전체 범위와 증명 조건

1. 새로운 질문·무응답과 원문 근거를 작성·검수하고 평가 파일 해시를 개선 전에 고정한다. 이전 33개 질문 및 동일 의도와 중복을 검사한다. 개발셋과 최종 검증셋은 문서/질문 의도로 분리한다. 같은 작성자가 원문 기반으로 만든 합성 검증은 현장 독립 검증과 구분하며 사람 검수를 대신했다고 주장하지 않는다.
2. 무응답 판정은 개발셋으로만 개선한다. 정상 적중률, 무응답 오탐, 제품·버전·권한 격리, 지연을 함께 측정한다. 검증셋 공개 후 그 결과에 맞춰 튜닝하면 그 세트는 개발용으로 전환하며 새 검증이 필요하다.
3. 원본을 유지하는 후보 생성으로 메뉴와 중복을 제거한다. 제목·절차·표·코드의 보존과 벡터 무효화를 테스트하고 원문/청크 근거 위치를 기록한다. 청킹 전후를 동일 질문으로 비교한다.
4. 실제 장문 다국어 임베딩의 모델/revision/입력/차원을 검증한다. 같은 코퍼스와 평가 조건으로 BM25 및 의미 검색을 비교하고 품질·무응답·비용·지연 근거로 채택한다. 모델명이나 임의 벡터를 실제 추론 결과로 취급하지 않는다.
5. 제품의 실제 답변 경로에서 질문·답변·인용·제품·버전을 평가한다. 문서 적중률과 답변 정확도를 별도 보고한다. 정답 근거 없는 응답과 잘못된 버전 주장은 실패다. 근거 불충분이면 불확실성을 표시한다.
6. 선행 PR과 신규 변경을 검토하고 필수 CI를 통과시킨 후 병합한다. 실제 배포 위치/현재 버전/데이터 권위를 확인하고 검증된 아티팩트를 배포한다. readiness와 실제 검색/답변 read-back을 기록해야 운영 완료다. 기존 서명 승인, 단일 사용 nonce, ACL 및 권위 저장소 게이트는 유지한다.

## 진행 증거: 평가 고정 및 무응답 개발 실험

- 836c078에서 새 질문 12개(6제품), 무응답 12개를 고정했다. fixture SHA-256 `7c7be3aa0c31a5ff4bd7bea0a626a9dac8b7eece935ad6bfad6d965030224623`. 이전 평가의 정답 소스와 겹침 0, 모든 정답 인용의 원문 위치·해시 확인. 사람의 독립 검수는 아직 없으며 합성 평가라는 한계를 manifest에 기록했다. 아직 이 세트의 검색 결과는 열지 않았다.
- `SANGFOR_RAG_REQUIRE_SUBJECT_MATCH=1` 실험: 기존 21문항 21/21, 개발 회귀 12문항 12/12 유지. 개발 무응답 오탐 1/4 → 0/4, 기존 무응답 0/4 유지. 요청 표현·제품/버전만 일치하는 결과를 거절한다. 확률 보정된 답변 신뢰도로 해석하면 안 된다. 현재 opt-in 상태이며 최종 승인 전이다.
- 개발 평가 명령: `SANGFOR_RAG_REQUIRE_SUBJECT_MATCH=1 pnpm run rag:eval:corpus <revision-v3 corpus-cleaned.json> <revision-v1-qrels-v2.json 또는 revision-v3-validation.json>`. 설정이 달라 기존 동일 설정 게이트에 비교 보고서를 넣지 않았다. 원시 결과는 docs/references/revision-v5/subject-*.json.
- BLRO의 실제 제품 파일 위치는 `/home/blro/orca/projects/sangfor-engineer-mcp`다. Git checkout이 아닌 파일 복사본이며 기본 3502/3600/3700 포트의 listener를 찾지 못했다. `start-mcp.sh`는 로컬 tsx stdio 서버를 실행한다. 현재 배포 여부는 더 검증해야 한다.
