- 상태: 구현 및 검증 완료 (PR #83 CI 통과). 후속 작업은 revision-v4-semantic-validation.md 참조.

## 고정 목표와 전환 조건
기존 `revision-v1-qrels-v2.json`의 질문, 정답, k=5 및 임계값을 변경하지 않는다. 66,767 청크 후보의 15/21(71.4%)에서 HitRate@5 >= 85%(최소 18/21)를 달성하고 기존 품질 게이트를 통과한다. 정답·임계값 변경 또는 합성 평가 결과로 대체하여 통과시키지 않는다. 당시에는 미달 시 LightRAG 도입을 계획했으나, 후속 사용자 지시로 이번 도입은 제외되었다. 자동 전환 조건은 더 이상 적용하지 않는다.

새로운 문서 기반 검증 질문과 정상 제품 범위의 무응답 평가를 추가하고 기존 질문과 따로 보고한다. 개발자가 작성한 평가셋을 독립적인 현장 검증으로 부르지 않는다. 의미 검색 및 재정렬은 실제 실행된 경로와 공급자 상태를 명시한다. 본 목표는 문서 단위 검색 품질이며 현장 해결률·답변 정확도 85%를 뜻하지 않는다.

## 순서 및 산출물
1. 기존 기준 결과와 평가셋 해시를 보존하고 별도 검증 질문을 검색 튜닝 전에 작성한다. 정답 근거를 기록한다.
2. 보수적 문서 정제를 구현한다. 수집 frontmatter와 알려진 탐색 메뉴만 제거하고 코드·표·명령어를 보존한다. 명시된 단일 문서 버전만 추출하고 모호한 버전을 추정하지 않는다. 기존 벡터에 새 임베딩 공간을 붙이지 않는다.
3. 정제된 본문·제목 기반 후보 검색을 개선한다. 일반적인 기술 약어/표현 정규화와 필드 검색을 적용하고 점수 없는 검색 결과를 반환하지 않는다. 고객·프로젝트·제품·버전 필터는 유지한다.
4. 의미 검색 공급자를 확인하고 가능한 실제 경로를 평가한다. 하이브리드 순위 결합을 선택 가능하게 만들고 기존 가중 합과 비교한다. 서비스가 없으면 이를 명시하고 해시를 의미 검색으로 보고하지 않는다.
5. 재정렬에 질문과 관련된 본문 구간을 제공하고 문서별 근거 손실을 점검한다. 공급자 오류·타임아웃·스키마 거절 시 원래 순위 보존을 검증한다.
6. 고정 평가셋과 추가 검증셋을 실행하고 각 모드/실패를 기록한다. 미달 시 원인을 보고한다. LightRAG 도입은 후속 사용자 지시에 따라 이번 범위에서 제외한다.
7. 단위 테스트, lint, build, 해당 CI를 수행하고 PR과 최종 결과를 기록한다. 인덱스 승격·운영 배포는 수행 사실이 있을 때만 완료로 표시한다.

## 위험과 검증
- 정제에 의한 근거 손실: 코드 블록/표/일반 YAML/메뉴 단어를 포함한 본문 보존 테스트.
- 기존 21문항에 과적합: 정답 ID/문서 ID 기반 규칙 금지, 별도 문서 기반 질문 결과를 별도로 보고.
- 의미 공간 혼합: 기존 호환성 검사와 고객 데이터 외부 전송 게이트 유지. 공급자 미가용은 명시적 lexical 결과.
- 무응답: zero-overlap 거절은 보장하되 일반적인 의미적 무응답 해결로 과장하지 않는다.

## 검증 결과
### 구현 결과
- 정제는 원문을 보존하는 검색 뷰와 신규 수집 양쪽에 적용했다. 코드·표 및 일반 YAML은 유지한다.
- 검색은 본문 BM25 + 구체적인 마지막 제목 절 BM25의 2배 가중치를 사용한다. 영어 불용어와 API 복수형 정규화, shell/CLI 및 standard/ordinary datastore 표현 확장을 적용했다. 문서 ID/정답 ID 기반 규칙은 없다.
- WeakMap 토큰 캐시는 청크 생존 기간에만 유지되며 텍스트 변경 시 재계산한다. IDF는 필터를 통과한 현재 후보 안에서 계산한다.
- RRF는 `SANGFOR_RAG_FUSION=rrf`로 선택 가능하다. 기본은 기존 가중 합이며 호환되지 않는 벡터의 비교는 여전히 거절한다.
- 어휘 근거 없는 BM25/해시 결과는 제외한다. 이는 보정된 의미적 무응답 판정이 아니다.
- 재정렬 입력은 단순 앞 400자 대신 정제된 본문의 질의 관련 연속 구간 최대 1,200자를 사용한다. 공급자 timeout/schema/ID 검증과 원래 순위 복구는 유지한다.
- `rag:prepare:candidate`는 새 파일만 만들며 원본/기존 출력 덮어쓰기를 거절한다. 66,767 청크를 보존했고, 18,472개 정제, 42,290개 명시 버전 추가, 본문 변경 청크의 벡터 18,472개 무효화를 확인했다. 운영 인덱스는 승격하지 않았다.
- 수집 함수 의미 변경에 따라 repository census digest를 재생성했다. 전후 persistence/credential/Prisma reference 목록은 동일하며 권한 manifest와 클래스 개수는 변경하지 않았다.

### 고정 평가 결과
| 항목 | 2차 기준 | 3차 정제 후보 |
|---|---:|---:|
| 기존 HitRate@5 | 15/21 (71.4%) | 20/21 (95.2%) |
| Recall@5 | 71.4% | 92.9% |
| MRR@5 | 0.5000 | 0.7817 |
| nDCG@5 | 0.5535 | 0.8065 |
| 기존 무응답 오탐 | 0/4 | 0/4 |
| 평균 검색 지연 | 208.5ms | 89.8ms |
| p95 검색 지연 | 378.3ms | 332.4ms |
| 고정 품질 게이트 | 목표 미달 | QUALITY_ELIGIBLE |

기존 질문·정답·임계값은 그대로다. RAID 한국어 문항 1개는 여전히 실패했다. Recall과 HitRate 차이는 CLI 문항에 정답 소스가 두 개 있기 때문이다. 이 결과는 **모두 BM25 경로**이며 의미 검색·LLM 재정렬의 성능으로 부르지 않는다.

### 별도 검증 결과와 한계
튜닝 전에 고정한 추가 12문항은 8/12(66.7%)에서 10/12(83.3%), 별도 무응답 오탐은 4/4에서 1/4로 개선됐다. 추가셋은 개발자가 작성한 영어 문서 탐색 질문이며 독립 현장 검증이 아니다. 별도셋 83.3%는 85% 미만이며 숨기지 않는다. 기존 고정 21문항 기준의 LightRAG 전환 조건은 발생하지 않았으나, 제품 전체의 85% 성능 달성을 주장하지 않는다. 추가셋 결과를 본 뒤 추가 튜닝하거나 정답을 수정하지 않았다.

기본 및 실제 프로젝트 설정 임베딩 endpoint가 모두 응답하지 않았다. 실제 의미 인덱스 재생성·Dense/RRF 품질 비교·외부 재정렬 효과 검증은 환경 미가용으로 수행하지 못했다. 공급자 부재를 해시 임베딩으로 대체해 의미 검색 성공이라고 보고하지 않았다. 기존 재임베딩 CLI와 새 정제 후보를 연결할 수 있으나 공급자 복구와 검증된 모델 revision이 필요하다. OCR, 전체 구조 기반 재청킹, 전용 Cross-encoder 도입, 피드백 학습은 이번 구현 범위에 포함하지 않았다.

전체 테스트와 동시에 실행한 중간 평가에서는 p95 게이트가 실패했다(558.5ms). 해당 결과도 `concurrent-load-candidate.json`으로 보존한다. 테스트 종료 후 정제 후보 단독 실행은 전체 게이트를 통과했다. 단일 실행 지연 수치는 운영 SLO가 아니다.

### 재현 명령
```bash
pnpm install --frozen-lockfile
pnpm run db:generate
pnpm run rag:prepare:candidate <v2-corpus.json> <new-v3-corpus.json>
pnpm --silent run rag:eval:corpus <new-v3-corpus.json> data/evals/rag/revision-v1-qrels-v2.json docs/references/revision-v3/baseline.json
pnpm --silent run rag:eval:corpus <new-v3-corpus.json> data/evals/rag/revision-v3-validation.json
TMPDIR=/home/jm/.cache/rag-v3-tmp pnpm test
pnpm run lint
pnpm run build
```

새 worktree는 frozen install 및 Prisma 생성 후 검증했다. 초기 공유 node_modules의 누락 의존성, /tmp 사용자 할당 한도, 긴 TMPDIR의 Unix socket 길이 오류는 실행 환경을 수정해 해결했다. 테스트/거절 조건은 약화하지 않았다.

단위 테스트 최종 결과: 3,211개 통과, 환경 의존 102개 skip. `pnpm run lint` 및 `pnpm run build` exit 0. CI 결과는 PR에서 추가 확인한다.

추가 검토에서 4자리 버전의 끝 3자리만 잘못 인식할 가능성을 차단했다. 해당 형식은 평가 코퍼스에 없음을 확인했으며, 회귀 테스트와 최종 평가를 다시 통과했다.
